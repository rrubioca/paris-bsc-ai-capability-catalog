# Security policy

This public catalog is a documentation artifact. It provides no laboratory access, credentials, deployable configuration or supported operational control interface. The pilot status is **UNDER VALIDATION — PARIS BSC LABORATORY**.

## Reporting a concern

Do not put vulnerabilities, sensitive evidence, internal identifiers or access details into a public issue, pull request or comment. If GitHub offers private vulnerability reporting for this repository, use that private flow. Its availability is not asserted here. Otherwise contact the repository owner through an existing verified private channel and request a secure reporting route before transmitting details. No unverified reporting address or response-time commitment is published.

Routine, non-sensitive broken links and wording corrections can use a public issue. This catalog does not provide vendor security support; use the relevant vendor's official process for product vulnerabilities.

## Publication boundary

Never commit live addresses, internal hostnames/domains, credentials, tokens, keys, connection strings, kubeconfig, remote-access instructions, administrative paths, access outputs, raw diagnostics, packet captures or detailed physical/network maps. Sanitization must also cover screenshots, image metadata, document contents, filenames and history. Replace operational identities with logical roles rather than reversible aliases or partially hidden values.

Functional topology must explain component roles and data dependencies without exposing a route into the private environment. This catalog does not verify identity integration, authorization, encryption, network isolation or other platform security controls.

If sensitive material is found, avoid repeating it publicly. Notify the owner privately, assess any affected credentials or access with the responsible security owner, and contain the disclosure through the appropriate private process. Editing the latest file alone does not remove material from Git history, caches or forks.
